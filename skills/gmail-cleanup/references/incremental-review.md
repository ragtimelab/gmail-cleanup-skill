# Inbox review scope and checkpoints

Use the connected Gmail tools for all mailbox operations. The checkpoint helper only manages local state.

- Default to the inbox of every connected account, or the named accounts if the user narrows the account scope. With a checkpoint, review the new inbox arrivals since that checkpoint. Without one, review the whole inbox. An explicit whole-inbox request also reviews the whole inbox. An explicit period or other message filter is a one-off review and does not change the checkpoint. Interpret user-defined periods in the user's timezone and use epoch seconds in Gmail date filters.
- Capture one run end with `date -u +%s` before querying Gmail. For each account in a default or full inbox review, run `python3 scripts/checkpoints.py begin ACCOUNT END` from the skill directory, adding `--full` for an explicitly requested full review. ACCOUNT is the connector account selector and END is the captured epoch second. Keep the returned token private and use the returned Gmail query for that account. The interval includes its initial second and excludes its end second. Gmail's search timestamp determines membership, not a sender's Date header.
- On `busy`, `lock_timeout`, `clock_regressed`, or `invalid_input`, skip the affected account and report the cause. On `storage_error` or `state_invalid`, report the returned phase and errno when present, and review the requested scope without a checkpoint. Check both the command exit code and its JSON. If no JSON is returned, record the command failure separately. For the default scope this means reviewing the whole inbox before END. A `cache_rebuild` result indicates unusable data was discarded. Report the rebuild. The helper preserves usable values for other accounts.
- Exhaust pages independently for each account. Reconcile exact IDs against `search_email_ids` with the same query for every review, including one-off and checkpoint-free reviews. Run `python3 scripts/verify.py reconcile` with account/ID pairs in `expected` (all ID search pages) and `reviewed` (classified details within scope). Recover missing details by exact ID when possible. Never compare an interval's coverage to the full INBOX label count. A repeated page token, unresolved missing item, required lookup failure, or interrupted classification makes the account incomplete. Report any coverage gap, omit its proposed candidates from approval, and do not advance its checkpoint. A completed judgment to hold an item is valid coverage. A successfully verified empty interval is valid coverage.
- During long reviews, call `python3 scripts/checkpoints.py renew ACCOUNT TOKEN` at least every 10 minutes. When the account's review and report are ready, with any proposal successfully sealed, call `python3 scripts/checkpoints.py finish ACCOUNT TOKEN` and report whether the checkpoint was saved. On a transient finish error, retry once with the same token before expiry. If no successful save can be confirmed, report the checkpoint outcome explicitly. Release unfinished accounts with `python3 scripts/checkpoints.py release ACCOUNT TOKEN`. If a token is lost or expires, report the affected account as incomplete and omit its proposal from the current approval request. A subsequent run can resume from the previous checkpoint. Gmail Trash approval and execution are separate from checkpoint advancement.
- An explicit checkpoint reset uses `python3 scripts/checkpoints.py reset [ACCOUNT]` and returns without mailbox operations. Omit ACCOUNT to reset all account checkpoints for this installation. If the helper reports `busy`, report that no reset occurred.
- Report each account's date range, number reviewed, number unread within that review, Trash candidate count, and checkpoint outcome. Show subjects and next actions for unread messages with a reply request, deadline, or security action. For a whole-inbox unread total requested separately, use the connector's INBOX label count. The default incremental review does not replay older mail after label or read-state changes. Use a full or period review for older mail.

## Storage diagnosis and recovery

Use `python3 scripts/checkpoints.py diagnose create` from the installed skill to test locking and atomic file replacement with an isolated synthetic marker. Compare its installation path and helper SHA-256 with the intended release. In a fresh session using the same execution route, run `diagnose read PROBE_ID` and then `diagnose clean PROBE_ID`. The probe never reads or writes account state. Report filesystem failures separately from a marker that did not persist. Incremental review requires both writable and persistent install-local storage. When access fails, use the full-scope read-only review path. A completed checkpoint-free review may produce a proposal subject to the same sealing, approval, and verification rules as other reviews.

Before upgrading, allow older active reviews to finish or expire and stop using the old helper against that installation. The new helper migrates compatible version 1 checkpoints under the existing lock and waits for legacy leases to expire. If state is invalid, halt checkpoint operations and preserve the cache for diagnosis. To rebuild, the operator first quiesces all runs, then moves the cache outside skill discovery paths and starts a full review. Keep the install-local cache as the sole source of persistent checkpoint state.
