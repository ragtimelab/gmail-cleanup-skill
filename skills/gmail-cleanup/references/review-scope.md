# Inbox review scope and coverage

- Default to the last seven days in the Inbox of every connected account. If the user names accounts, apply the same default to those accounts. Include both read and unread mail. An explicit time range or whole-inbox request replaces the seven-day window. Apply any other requested filter within that window unless the user specifies a different date scope. An old request to reset checkpoints does not trigger a review. Explain that checkpoints were retired.
- Capture END once with `date -u +%s` before querying Gmail. Run `python3 -B scripts/verify.py query END` for the default, add `--full` for the whole inbox, or supply `--start START` and use the earlier of END and the requested upper boundary for an explicit period. Interpret user-specified dates in their timezone. The starting second is included and the ending second excluded. Use Gmail's search timestamp, regardless of a sender's Date header.
- Exhaust all pages of `search_emails` and `search_email_ids` independently per account using the same final query. Use account/ID pairs in `expected` (the ID search results) and `reviewed` (classified messages within scope) with `python3 -B scripts/verify.py reconcile`. Recover missing detail by exact ID when possible. A repeated page token, unresolved ID discrepancy, required lookup failure, interrupted classification, or unavailable validator leaves the affected account incomplete. Report the gap and omit its candidates from approval. A completed decision to hold an item and a verified empty window both count as valid coverage.
- Report each account's exact review window, reviewed and unread counts in that window, and Trash candidate count. Surface messages with an outstanding reply, deadline, or security action regardless of read state. Give the specific action and any known deadline, separately from the Trash approval request. If the user asks separately for total inbox unread, use the INBOX label count. Offer a longer period or the whole inbox when older mail matters.
